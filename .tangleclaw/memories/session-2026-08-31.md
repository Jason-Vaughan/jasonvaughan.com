**Lessons Learned:**
- **MCP Browser Agent limitation on macOS:** Attempting to spawn an isolated, secondary Chrome profile using `--remote-debugging-port=9222 --user-data-dir=$(mktemp -d)` locks out the Antigravity `chrome_devtools` MCP server. The MCP connector strictly looks for `DevToolsActivePort` in the *default* profile directory (`~/Library/Application Support/Google/Chrome/`), and manually creating or symlinking the file into that directory does not bypass the connection failure. To use browser automation, the target Chrome process must be running out of the default profile directory.

- **PostHog NPM initialization quirk:** Because we use the native `posthog-js` import instead of the HTML snippet, `window.posthog` is undefined on the live site by design. Do not try to attach it to window. Also, PostHog Web Analytics tiles cache heavily—use "Installation Health" to verify data pipeline instead of just staring at the tile.
